# iOS 启动页实现与复用

本文记录 WristTrip 当前启动页的实现，供后续 iOS App 复用。

## 当前启动流程

```text
iOS 启动
  → LaunchScreen.storyboard（系统静态启动图）
  → WristTripRootView 显示 SwiftUI 启动画面
  → ContentView 报告就绪，且启动页至少显示 700 ms
  → 启动画面淡出
  → 首次安装且未完成引导时显示 onboarding
```

系统启动图由 iOS 在 App 首屏加载前显示；它必须是静态、轻量的视图。SwiftUI 启动画面属于 App 内容，可以执行计时、响应主题并使用过渡动画。两者的背景、Logo 尺寸、标语、垂直间距和整体位置保持一致，因此系统画面交接给 SwiftUI 时不容易出现闪烁或跳动。

## 文件职责

| 文件 | 用途 |
| --- | --- |
| `WristTrip/Info.plist` | `UILaunchStoryboardName = LaunchScreen`，告诉 iOS 使用哪个 storyboard。 |
| `WristTrip/Resources/LaunchScreen.storyboard` | 系统静态启动图：背景色、78×78 Logo、标语和居中偏上 24 pt 的布局。 |
| `WristTrip/Resources/LaunchScreenLogo.png` | storyboard 引用的系统启动 Logo。 |
| `WristTrip/Resources/Assets.xcassets/LaunchBackground.colorset/Contents.json` | 启动背景颜色，提供浅色与深色外观。 |
| `WristTrip/Resources/Assets.xcassets/LaunchLogo.imageset/` | SwiftUI 启动画面使用的 1x/2x/3x Logo。 |
| `WristTrip/LaunchView.swift` | SwiftUI 启动画面；按指定外观解析背景与文字颜色，至少显示 700 ms 后通知外层。 |
| `WristTrip/WristTripApp.swift` | 根视图协调启动状态、主题、淡出和首次启动引导。 |
| `WristTrip/ContentView.swift` | `onReady` 在场景进入 active 后触发，向根视图报告主内容已可呈现。 |

## 状态与退出条件

根视图分别维护两个状态：

- `contentReady`：主内容通过 `ContentView(onReady:)` 报告就绪。
- `minimumLaunchDurationElapsed`：`WristTripLaunchView` 的 `.task` 等待 700 ms 后报告完成。

只有两个状态都为 `true`，启动页才移除。因此内容较快准备好时，启动页仍至少显示 700 ms；内容准备较慢时，启动页继续覆盖内容，直到收到就绪回调。移除使用 0.2 秒淡出。计时任务被取消时不会调用完成回调。

这里的“内容就绪”表示场景已 active，且主内容的 active task 已启动；它目前不等待车票读取或网络请求全部完成。若其他 App 必须等关键数据加载完成后再展示主界面，应把 `onReady` 放到对应的数据准备完成点，而不是单纯的场景激活回调。

启动页消失之后，根视图再检查 `wristTrip.hasCompletedOnboarding`。值为 `false` 时显示首次启动引导；引导完成后写为 `true`，下次启动不再出现。

## 主题处理

外观偏好保存在 `@AppStorage("wristTrip.appearanceMode")`。启动页解析主题时优先使用用户选择的浅色或深色模式；选择系统模式时跟随当前系统 `colorScheme`。同一个解析后的主题用于：

- 启动画面的背景颜色集；
- 启动画面标语的系统 label 颜色；
- 根视图的 `.preferredColorScheme`。

这样系统 LaunchScreen 与 SwiftUI 启动画面都能在浅色和深色模式下使用匹配的外观。

## 后续 App 复用步骤

1. 在目标 App 的 `Info.plist` 配置 `UILaunchStoryboardName`，添加静态 LaunchScreen storyboard。
2. 准备启动背景颜色集，至少提供浅色和深色外观；storyboard 和 App 内启动页引用同一颜色资源。
3. 准备启动 Logo。系统 LaunchScreen 与 SwiftUI 可分别使用项目所需的资源格式，但视觉尺寸、留白和裁切要一致。
4. 建立 SwiftUI 启动画面，只放品牌 Logo、短标语等轻量内容；保持它与 storyboard 布局一致。
5. 在 App 根视图中并行等待“主内容就绪”和“最短展示时间结束”，两者满足后再移除启动页。
6. 如果有 onboarding，将它作为启动页之后的独立状态处理，并持久化完成标记。
7. 在浅色、深色、慢速初始化和首次启动路径下检查两段启动画面的背景、位置、时长及交接效果。

## 设计与维护约束

- 系统 LaunchScreen 保持静态，不在其中执行动画、网络请求或业务逻辑。
- 最短展示时间只用于避免一闪而过的启动页；应按目标 App 的观感调整，不用它模拟加载进度。
- 就绪回调应对应真实的“首屏可呈现”时点。不要因无关的后台任务或非必要请求延迟首屏。
- storyboard 和 SwiftUI 使用相同品牌素材与布局参数；更新 Logo 或文案时应同步修改两处。
- 若应用没有首次引导，可删去 onboarding 状态，保留启动页的双条件退出逻辑。
